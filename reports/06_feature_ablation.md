# 06. 피처 절제 실험 — v2 피처 21개는 값을 하는가 (재튜닝 포함 2×2) + `T_soft` 격자 확장

**결론 두 줄: v2 피처 21개는 기각(D−A′ = +0.0006, 노이즈의 0.4배). 그런데 피처를 하나도 안 바꾸고 하이퍼파라미터만 재튜닝한 A′가 현 확정 모델을 +0.0029(3.5배)로 넘었다 — 이쪽이 이번 실험의 진짜 산출물이다.**

**후속(§12): `T_soft` 봉우리를 0.001에서 격자 안에 가뒀다. 홀드아웃 이득이 A′ 대비 +0.0005(0.7배)로 구분되지 않아 둘 다 제출했는데 — 리더보드에서 둘 다 역행했고, 순위가 홀드아웃과 정확히 반대로 나왔다(아래 "리더보드 결과").**

| | 블렌드 | 1−NMAE | FICR |
|---|---:|---:|---:|
| A 현 확정 모델(exp017) | 0.6458 | 0.8744 | 0.4172 |
| **A′ v1 피처 + 재튜닝** | **0.6487** | 0.8744 | **0.4231** |
| D v2 피처 + 재튜닝 | 0.6493 | 0.8761 | 0.4225 |
| **A″ A′ + `T_soft` 0.001** | **0.6492** | 0.8740 | **0.4245** |

## Why

`03_features.ipynb`는 피처를 두 벌 만들어 저장해 뒀다 — v1(179개, 현 확정 모델이 쓰는 것)과 v2(200개 = v1 + 21개). v2의 21개는 문헌을 다시 읽고 도출한 결빙 지속성·구름/안개·복사 안정도·풍향 시어 네 묶음인데, **만들어만 놓고 효과를 한 번도 재지 않았다.**

효과를 재려니 문제가 하나 드러났다. **블렌드까지 포함한 홀드아웃 점수를 계산하는 코드가 저장소에 없었다.**

- `train.ipynb`는 2022~2024 전체로 학습한다(홀드아웃을 남기지 않는다)
- `inference.ipynb`는 2025 test를 예측한다(정답이 없어 채점 불가)
- `05_tuning.ipynb`는 **LightGBM 단독**만 2024로 잰다(0.6308). MLP도 블렌드도 없다

즉 확정 모델의 성능 근거인 **2024 홀드아웃 0.6458은 `reports/train.md`에 숫자로만 남아 있고 재계산할 수단이 없었다.** 그래서 이 노트북은 피처를 재기 전에 **하네스부터 만들었다.**

그리고 공정한 비교의 조건이 두 개라는 것을 설계에 반영했다.

| 함정 | 내용 |
|---|---|
| ① 옛 설정을 씌우면 **v2가 불리** | 현 설정(τ·`T_soft`·w)은 v1에 맞춰 고른 값이다. 피처가 바뀌면 최적 설정도 움직인다 |
| ② 재튜닝만 하면 **v2가 유리** | "v2+새설정 > v1+옛설정"이면 이득이 피처 덕인지 설정 덕인지 구분이 안 된다 |

②는 이 프로젝트가 실제로 빠졌던 함정이다 — 피처와 하이퍼파라미터를 함께 바꿔 +0.0036이 나왔는데, 바뀐 설정을 옛 피처에 적용해 보니 +0.0024가 설정 덕이고 피처 순효과는 +0.0012(노이즈)였다.

## How

1. **2024 홀드아웃 하네스 구축(§2)**: `train.ipynb`가 하는 일을 시간만 1년 앞으로 밀어서 그대로 한다 — 2022~2023 학습, 내부검증 2023 하반기(트리 수·에폭 수 결정), 2024 채점. LightGBM 분위수 회귀(actual 표본가중) + MLP(산식 손실, 시드 5개 평균)를 그룹별 가중 블렌드. 하이퍼파라미터는 인자로 받아 네 칸이 같은 코드를 쓰게 했다.

2. **하네스 검증(§3)**: 노트북 작성 중 LightGBM 경로만 따로 돌려 `experiments/log.csv`의 exp011과 대조 → `0.630751 / 0.863555 / 0.397948`로 **소수점 여섯 자리까지 일치**. 본 실행에서는 MLP·블렌드까지 포함해 `reports/train.md` 기록값(0.6308 / 0.6435 / 0.6458)과 **소수점 네 자리까지 일치**했다.

3. **2×2 디컨파운드 설계(§7)**: 피처 2수준 × 설정 2수준.

   | | v1 피처(179) | v2 피처(200) |
   |---|---|---|
   | v1 기준 설정 | **A** 확정 모델 / **A′** v1 재튜닝 | **B** |
   | v2 기준 설정 | **C** (교란 제거 팔) | **D** |

   A′를 따로 둔 이유는 두 설정이 **같은 절차**에서 나와야 "절차가 같은데 피처만 다른" 비교가 되기 때문이다. 동시에 A′−A는 "튜닝 절차가 과거 결정을 재현하는가"를 잰다.

4. **재튜닝은 2022~2023 안에서만(§4~6)**: 2024는 채점에만 쓴다.

   | 대상 | 탐색 장소 | 방법 |
   |---|---|---|
   | LightGBM τ·코어 | 2022~2023 4폴드 CV | τ 격자 6개 **와** Optuna 20회 → CV 높은 쪽을 그룹마다 채택 |
   | MLP `T_soft` | 내부검증(2023 하반기) | [0.003, 0.006, 0.012, 0.025] |
   | 블렌드 w | 내부검증(2023 하반기) | 0~1, 0.05 간격. 위 예측 재사용이라 추가 학습 없음 |

   홀드아웃 위에서 설정을 고르면 그 점수는 낙관적으로 부풀려진다. **다만 확정 모델의 w(0.8/0.5/0.9)는 과거에 이 홀드아웃 위에서 고른 값이라, 이번 비교는 A 쪽에 유리하게 기울어 있다** — 그럼에도 A′가 이겼다면 결론이 보수적으로 안전하다는 뜻이다.

5. **판정(§8)**: 시드 5개 각각으로 블렌드 점수를 따로 내 흔들림을 재고, 시드 5개 평균의 표준오차를 노이즈 기준으로 삼았다. 비교마다 **그 비교에 참여하는 두 칸만의 쌍별 표준오차** `sqrt(s_a²+s_b²)`를 쓴다.

6. **묶음별 절제(§9)**: `feature_manifest.json`의 `v2_blocks` 네 묶음을 하나씩만 v1에 더해 재는 절차. **§8이 기각이면 자동으로 건너뛴다**(`RUN_ABLATION` 플래그). 이번엔 건너뛰었다.

7. **`T_soft` 격자 하방 확장(§12)**: §5·§6이 둘 다 격자 최솟값 0.003을 골라 봉우리가 안 갇혔으므로, `[0.0005, 0.001, 0.002, 0.003, 0.004]`로 아래를 열어 다시 훑었다. 선택은 §4-2와 똑같이 **내부검증(2023 하반기)에서만** 하고, 고른 뒤 2024를 한 번 채점했다(칸 A″). 세 가지를 설계에 넣었다.
   - **재현 검증을 격자에 심었다**: 0.003을 일부러 포함해 §5 값(0.6196)이 그대로 나오는지 자동 대조. 통과했다.
   - **§5 결과를 파일로 영속화**(`experiments/hp_v1_retuned.json`): §5의 Optuna 코어 파라미터가 메모리에만 있어 커널이 죽으면 6분을 다시 써야 했다. 이후 실험도 이 파일을 재사용한다.
   - **그룹별 최적 `T_soft`도 함께 출력**: 공통값 하나로 묶는 게 손해인지 미리 보려는 것(할 일 5-(b)의 사전 신호).

### v2 피처 — 기각

세 개의 피처 효과 추정치(D−A′ 0.4배, D−C 1.0배, B−A′ 0.7배)가 전부 노이즈 안이고 방향도 일관된다. 피처 실험 8번째 실패다.

한 가지는 짚어 둔다. **v2는 1−NMAE를 실제로 올렸다**(0.8744 → 0.8761). 그런데 FICR이 그만큼 내려(0.4231 → 0.4225) 총점에서 상쇄됐다. 추가 피처가 예측 정확도 자체엔 조금 기여했지만, 이 산식에서 점수를 만드는 것은 **6%/8% 밴드 안에 들어가느냐**이고 거기엔 도움이 안 됐다.

CV(2022~2023, LightGBM 단독)에서도 v1 0.6085 → v2 0.6071(−0.0014)로 같은 방향이었다. 홀드아웃과 독립된 증거가 같은 곳을 가리킨다.

### 재튜닝 — 채택 검토 대상

| | 확정값(A) | 재튜닝(A′) |
|---|---|---|
| `T_soft` | 0.006 | **0.003** |
| g1 τ / w | 0.70 / 0.80 | 0.663 / **0.65** |
| g2 τ / w | 0.50 / 0.50 | 0.50 / **0.35** |
| g3 τ / w | 0.65 / 0.90 | 0.663 / **0.85** |

그룹별 블렌드 점수: g1 0.6512 → **0.6600(+0.0088)**, g2 0.6764 → 0.6738(−0.0026), g3 0.6099 → 0.6124(+0.0025).

**신호를 믿을 만하게 만드는 근거 세 가지**

1. **1−NMAE는 0.8744로 완전히 그대로인데 FICR만 +0.0059 올랐다.** `T_soft` 0.006 → 0.003은 계단 함수를 더 날카롭게 근사하는 것이고 그 직접적 타깃이 FICR이다. 원인과 결과가 정확히 맞는다. 이 프로젝트에서 리더보드로 검증된 개선(τ → FICR 손실 → 그룹별 손실)이 전부 이 "산식을 더 정확히 겨냥" 계열이었다.
2. **A′의 설정은 2024를 한 번도 보지 않고 골랐다.** 반면 확정값의 w는 과거에 이 홀드아웃에서 고른 값이라 A 쪽이 유리했는데도 졌다.
3. g1이 개선의 대부분을 만들었는데, g1은 확정값에서 τ=0.70·w=0.80으로 가장 세게 위로 밀던 그룹이다. 그 강도를 낮춘 것이 맞았다는 해석과 일치한다.

### `T_soft`가 격자 경계에서 멈췄다 → §12에서 봉우리를 찾았다

2×2 실행 시점의 후보 `[0.003, 0.006, 0.012, 0.025]` 중 **v1·v2 둘 다 최솟값 0.003**을 골랐다. 봉우리가 격자 안에 갇히지 않았다는 뜻이라 §12에서 아래를 열었다.

**§12-1에서 세운 기전 예측**: `T_soft`를 낮추면 두 가지가 동시에 일어난다 — 손실이 실제 계단(4/3/0)에 가까워지는 대신, **기울기가 살아 있는 구간이 밴드 경계 ±T 창 안으로만 좁아진다**(시그모이드 미분은 경계에서 멀어지면 지수적으로 죽는다). `T=0.0005`면 그 창은 g1 기준 **±10.8 kWh**(설비의 0.05%)다. 게다가 창 안에서는 기울기 크기가 `1/T`로 커져 `GRAD_CLIP=1.0`에 계속 걸린다. **따라서 아래 어딘가에 반드시 봉우리가 있어야 한다.**

**결과 — 예측이 맞았다.**

| `T_soft` | 내부검증 평균 | |
|---:|---:|---|
| 0.0005 | 0.6256 | |
| **0.001** | **0.6265** | **← 최적, 양옆이 모두 낮다** |
| 0.002 | 0.6203 | |
| 0.003 | 0.6196 | §5의 선택 (재현 확인 통과) |
| 0.004 | 0.6173 | |
| 0.006 | 0.6173 | 확정 모델의 값 |
| 0.012 | 0.6152 | |
| 0.025 | 0.6109 | |

0.001에서 정점을 찍고 **0.0005에서 다시 내려간다(−0.0009).** 위 상충이 실제 데이터에서 확인된 것이고, 봉우리가 양옆으로 갇혔으므로 **이 축은 더 팔 것이 없다.**

### ★ 내부검증의 개선이 홀드아웃에서 11%만 실현됐다

| 칸 | `T_soft` | w (g1/g2/g3) | 2024 블렌드 | 1−NMAE | FICR | 시드노이즈 |
|---|---:|---|---:|---:|---:|---:|
| A (확정) | 0.006 | 0.80 / 0.50 / 0.90 | 0.6458 | 0.8744 | 0.4172 | 0.00050 |
| A′ | 0.003 | 0.65 / 0.35 / 0.85 | 0.6487 | 0.8744 | 0.4231 | 0.00066 |
| **A″** | **0.001** | **0.60 / 0.30 / 1.00** | **0.6492** | 0.8740 | **0.4245** | 0.00039 |

| 비교 | 값 | SE | 배수 |
|---|---:|---:|---:|
| A″ − A′ (격자 확장의 순효과) | +0.0005 | 0.00077 | **+0.7** |
| A″ − A (확정 모델 대비 총 이득) | +0.0034 | 0.00063 | **+5.4** |

내부검증에서 블렌드 점수는 A′ 0.6245 → A″ 0.6290으로 **+0.0045** 올랐는데, 홀드아웃에서는 **+0.0005**만 실현됐다. 내부검증 구간은 **2023년 하반기 6개월**뿐이다. 그 6개월로 `T_soft`를 0.003 → 0.001로 세 배 가까이 좁히는 선택을 한 것인데, **그 구간에만 맞는 값을 고른 것**으로 보인다. 곡선이 0.002 → 0.001에서 계단처럼 튄 것(+0.0062)도 같은 이야기다 — 매끄러운 최적화가 아니라 특정 구간에 우연히 잘 맞은 점을 집은 모양이다.

**교훈: 이 하네스로 후보를 고를 때 내부검증 개선폭을 액면 그대로 믿으면 안 된다.** 앞으로 남은 실험(그룹별 `T_soft`, 그룹별 MLP 구조, 조건부 블렌드 w)이 전부 같은 내부검증으로 고르는 실험이라 특히 그렇다.

다만 **A″가 A보다 나은 것은 확실하다** — `A″ − A = +0.0034(5.4배)`로 A′(3.5배)보다 오히려 강하고, 시드노이즈도 0.00039로 셋 중 가장 작다. 패턴도 여전하다: **1−NMAE는 0.8744 → 0.8740으로 오히려 조금 내려갔는데 FICR이 0.4231 → 0.4245로 올라 총점을 만들었다.**

### §12의 부산물 둘

**(a) 그룹별 `T_soft`(할 일 5-(b))의 사전 신호**

| 그룹 | 그룹별 최적 `T_soft` | 공통 0.001 대비 |
|---|---:|---:|
| g1 | 0.0005 | +0.0000 |
| **g2** | **0.002** | **+0.0017** |
| g3 | 0.001 | +0.0000 |

**g2만 다른 값을 원한다.** 세 그룹 중 가장 잘 맞는 그룹(NMAE 0.1265)이 오히려 **더 뭉갠 손실**을 원한다. 다만 위의 실현율 11%를 감안하면 이 +0.0017도 액면 그대로 볼 수 없다 — 축은 유효하되 기대는 낮춰 잡는다.

**(b) g3의 블렌드 가중치가 w=1.00으로 갔다 — LightGBM을 완전히 버렸다**

격자 상한값이다. g3 예측의 **100%를 MLP가 만든다**는 뜻이고, 두 모델의 오차가 상쇄되는 블렌드의 이점을 g3에서는 포기한 것이다. 구v5 `05_tuning_1` 14-8에서도 똑같이 나왔고 해석도 같았다 — *"라벨 기간이 짧아 데이터가 적은데, MLP의 매끄러운 함수 근사가 이런 소규모·저신호 상황에서 트리보다 덜 과적합했을 가능성"*. **g3 병목 = 표본 부족을 가리키는 여섯 번째 경로다.**

그리고 이것이 **다음 실험(g3만 통합 학습)의 기대치를 올린다** — w=1.00이면 g3 MLP의 개선이 g3 점수에 **100% 그대로** 반영되고, g3는 총점의 3분의 1이다.

### 판정 로직 버그 (정직한 기록)

첫 실행에서 §8이 **"기각 — 확정 모델 유지, train/inference/src 무변경"** 을 출력했으나 **틀린 판정이었다.** 분기가 `D − A′`를 먼저 보고 3배 미만이면 그 자리에서 종료하도록 짜여 있어 **`A′ > A`인지를 아예 검사하지 않았다.** "피처 기각 / 설정 채택" 갈래를 결정 축 통과 이후에만 도달하게 배치한 설계 실수다. 두 가지를 고쳤다.

- 판정을 **(1) 피처 / (2) 설정** 두 개로 완전히 분리하고, (2)는 (1)의 결과와 무관하게 **항상** 검사하게 했다.
- 노이즈를 전역 최댓값에서 **쌍별 표준오차**로 바꿨다. `A′ − A` 비교에 D칸(가장 노이즈가 큰 칸)의 흔들림을 쓰던 것을 고쳐, 배수가 2.5 → **3.5**가 됐다.

## So-what

- **v2 피처 21개는 채택하지 않는다.** `features_v2_*.parquet`는 재현성을 위해 남기되 `train.ipynb`/`inference.ipynb`는 v1(179개)을 계속 쓴다. 이 방향은 종료.
- **하이퍼파라미터 레버가 아직 남아 있었다.** "확정 모델은 이미 최적"이라고 암묵적으로 가정하고 있었는데 사실이 아니었다. A′ 구성(+0.0029/3.5배)은 **제출로 확인할 가치가 충분하다** — 크기도 문턱을 넘고, 성격이 이 프로젝트에서 리더보드로 검증된 계열과 같으며, 홀드아웃을 보지 않고 고른 값이다.
- **`T_soft` 축은 종료.** §12에서 봉우리가 0.001에 갇혔고, 12-1의 기전 예측대로 그 아래에서는 무너진다. 더 팔 것이 없다.
- **A′와 A″를 둘 다 제출한다.** 홀드아웃에서 구분되지 않으므로(0.7배) 로컬로는 가릴 방법이 없다. 제출은 하루 5회 가능하고 마감까지 여유가 있으며, 이 비교는 *"내부검증 6개월로 하이퍼파라미터를 잘게 고르는 것이 실제로 되는가"* 에 대한 실측 답을 준다 — 남은 실험이 전부 같은 내부검증에 의존하므로 그 답이 이후 판정 기준에 직접 영향을 준다.
- **`train.ipynb`에 구성 스위치를 넣었다**: `CONFIGS` 딕셔너리 + `CONFIG_NAME` 한 줄(`"exp017"` / `"A2"` / `"A3"`). 값을 손으로 옮겨 적다 한 군데를 빠뜨리는 사고를 막고, 현 리더보드 최고 기록(exp017)도 언제든 그대로 재현할 수 있게 했다. A′·A″는 **그룹마다 LightGBM 코어 파라미터까지 다르므로** `LGB_PARAMS_BY_GROUP`을 쓴다. `config.json`이 `exp_id`까지 들고 있어 `inference.ipynb`가 제출 파일명을 자동으로 맞춘다.
- **다음은 구조 레버(g3만 통합 학습).** 비교 기준선은 A가 아니라 **리더보드가 더 낫다고 판정한 쪽**(A′ 또는 A″)이다.
- **이 노트북이 남긴 재사용 자산**: §2 홀드아웃 하네스와 §4 재튜닝 도구는 앞으로의 모든 실험(단조 제약, 그룹별 `T_soft`, g3 통합, 조건부 블렌드 w)이 그대로 쓴다. **제출해 봐야 아는 상태에서 벗어나, 2024에서 먼저 재고 갈 수 있게 됐다** — 이것이 v2 기각보다 이번 세션의 더 큰 산출물일 수 있다.
- **방법론 교훈 2 (§13에서 추가)**: 홀드아웃 이득이 리더보드 이득으로 이어지는지를 **홀드아웃 안에서** 알아내려는 시도는 두 번 다 실패했다. 제출이 값싼 상황에서는 **탐지기를 만드는 것보다 그냥 제출해 보는 것이 빠르고 정확하다.**
- **방법론 교훈**: 2×2에서 대각선(D−A′)만 판정 축으로 삼으면, **기준선 자체가 갱신되는 경우**(A′>A)를 놓친다. 처치를 재는 실험이라도 "대조군을 다시 만드는 과정"에서 개선이 나올 수 있으므로, 판정 분기는 모든 축을 독립적으로 검사해야 한다.

## 리더보드 결과 — 홀드아웃 순위가 정확히 뒤집혔다

A′·A″를 둘 다 제출한 결과다(2026-07-29).

| 구성 | 홀드아웃(2024) | **Public(2025)** | 오프셋 | vs exp017 | 1−NMAE | FICR |
|---|---:|---:|---:|---:|---:|---:|
| **A (exp017)** | 0.6458 (3위) | **0.638863 (1위)** | −0.0069 | — | 0.8650 | 0.4128 |
| A′ (exp028) | 0.6487 (2위) | 0.634459 (2위) | −0.0142 | −0.0044 | 0.8620 | 0.4069 |
| A″ (exp027) | **0.6492 (1위)** | 0.631730 (3위) | **−0.0175** | −0.0071 | 0.8602 | 0.4032 |

**홀드아웃 순위 A″ > A′ > A, Public 순위 A > A′ > A″.** 오프셋도 −0.0069 → −0.0142 → −0.0175로 단조 증가한다 — 확정 모델에서 멀어진 거리만큼 리더보드가 나빠졌다. 두 지표가 둘 다 같은 순서로 늘어섰다.

**겨냥한 지표에서 반대 결과가 났다.** `T_soft`를 낮춘 근거는 "계단을 더 날카롭게 근사하면 FICR이 오른다"였고 2024에서는 실제로 그랬다(0.4172 → 0.4231 → 0.4245). 2025에서는 **0.4128 → 0.4069 → 0.4032로 정확히 뒤집혔다.**

**분해는 깨끗하다.** A′와 A″는 LightGBM 파라미터가 같아 트리 모델 파일이 비트 단위로 동일했다(해시 `8bfbc67f27de9720`, 트리 수 117/198/85 일치). 따라서 둘의 차이 −0.0027은 **순전히 `T_soft`와 `w`에서** 나온 것이고, A → A′의 −0.0044가 나머지(LightGBM 코어·τ 포함)다. 두 단계 다 손해였다.

### 이 실패의 성격 — 눈금 재적합 3연패

| 실패 | 홀드아웃 | Public | 무엇을 바꿨나 |
|---|---:|---:|---|
| 사후 affine 보정 | +0.0029 | −0.0087 | 예측을 `a·pred+b`로 재보정 |
| A′ | +0.0029 | −0.0044 | τ·`w`·`T_soft` 재적합 |
| A″ | +0.0034 | −0.0071 | 위 + 더 극단적으로 |

셋 다 **캘리브레이션(예측을 얼마나 위로 밀고 밴드를 얼마나 세게 쫓을지)을 짧은 최근 구간에서 다시 맞춘 것**이다. 반대로 리더보드에서 먹혔던 것(FICR 손실 +0.0030, 그룹별 손실 +0.0035, 하이브리드 구조 +0.0004)은 전부 **목적함수 또는 학습 데이터 구성**을 바꾼 것이다. 3승 3패가 이 경계선을 따라 갈린다.

눈금은 그 해의 바람 분포에 붙어 있다 — 2024와 2025는 풍속 분포가 다르고, 6%/8% 밴드 적중은 예측 수준이 조금만 어긋나도 크게 흔들린다.

### 하네스로 채택을 판정하려 했으나 기각했다 (§13)

§2 홀드아웃 하네스는 **첫 실전 시험에서 순위를 정확히 반대로 매겼다.** 시드 노이즈 대비 5.4배라는 신호가 리더보드에서 역행했다. §8이 재는 노이즈는 **시드(난수)를 바꿨을 때의 흔들림**인데, 정작 걱정해야 할 것은 **연도가 바뀌었을 때의 흔들림**이었다.

그래서 2024를 12개월·4분기로 쪼개 판정하는 기준을 두 번 시도했고, **둘 다 실패했다.**

| 시도 | A′(실패) | A″(실패) | **블렌드 도입(성공, Public +0.0160)** | 결과 |
|---|---|---|---|---|
| ① 부호 일관성(양수 구간 비율) | 통과 ❌ | 경고 ✔ | 통과 ✔ | A′를 놓침 |
| ② 시간 추세(기울기·Kendall τ) | 경고 ✔ | 경고 ✔ | **경고 ✘** | 성공까지 경고 |

②는 실패 두 건을 다 잡아 유망해 보였으나, **리더보드에서 실제로 성공한 변경(exp016 → exp017)에도 경고**를 띄웠고 추세 외삽은 부호까지 틀렸다(예측 −0.0028, 실제 +0.0160). 즉 **"이득이 2024 안에서 시간에 따라 감소한다"는 것은 실패의 특징이 아니라 이 데이터의 일반 성질**이다.

문턱을 다시 조정하면 3/3을 맞출 수 있지만 하지 않았다 — 지표를 이미 두 번 갈아 끼웠고, 표본이 3개뿐이며 그중 둘(A′·A″)은 LightGBM이 비트 단위로 같아 사실상 독립이 아니다. 세 번째 조정은 데이터를 설명하는 게 아니라 외우는 것이다.

**그리고 애초에 이 도구가 필요하지 않았다.** 마감까지 하루 5회 × 16일 ≈ 80회 제출이 가능한데 남은 후보는 6~8개다. **후보 하나당 열 번씩 제출할 수 있다.** 제출 몇 번을 아끼려고 탐지기를 만들고 검증하는 데 반나절을 쓴 것이 판단 착오였다.

**→ 원칙: 홀드아웃 하네스는 (a) 변형을 싸게 비교해 후보를 좁히고 (b) 코드가 망가지지 않았는지 확인하는 데 쓴다. 채택은 제출로 판정한다.** 판정 관련 코드는 전부 삭제했고, 구간별 채점 도구(`segment_scores`)만 오류 분석용으로 남겼다.
